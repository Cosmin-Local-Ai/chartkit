# Venue fixtures

Files here are messages each adapter must parse. Every file says where it came from,
because an undocumented fixture is a fixture that lies later.

Two kinds appear, and the difference matters:

- **transcribed** — copied from the vendor's own documentation. The URL is in the file.
  These are the strongest evidence the parser has: the vendor wrote the example.
- **synthesized** — written by hand to the shape the vendor documents, because the docs
  describe the fields but give no example, or the case (a gap, a delayed entitlement) is
  not in any example. Field names, order and types come from the doc page named in the
  file; the numbers are ours.

## rithmic/ — Rithmic R|Protocol (Protocol Buffers over WebSocket)

Rithmic publishes the transport but not the schema: "R|Protocol API uses WebSockets and
Google protocol buffers" (https://www.rithmic.com/apis, archived at
https://web.archive.org/web/2025/https://www.rithmic.com/apis). The `.proto` files ship
with the R|API+ download behind a reseller login, so no Rithmic example message was
reachable from here.

| file | provenance |
| --- | --- |
| `frames.json` | synthesized — hex-encoded frames, 4-byte big-endian length plus protobuf body, encoded from the message shapes in the transcribed `.proto` set at https://github.com/parbhatc/Rithmic/tree/main/proto |

`frames.json` is regenerated by `cargo test -p chartkit-ingest emit_fixtures -- --ignored`.
Treat the first live run of `chartkit --check-feed rithmic` as the check on the template
ids and field numbers: they come from a third-party transcription, not from Rithmic.
